# Задача 2. Справочник товаров

Напишите быстрый справочник, который хранит много пар «артикул - товар».
Пользователь запрашивает товар по артикулу - программа мгновенно его возвращает. Если значения
нет - программа «идёт искать» (долгий запрос, например 1 секунда) и сохраняет результат, чтобы
в следующий раз отдать сразу. Кэш ограничен: при переполнении удаляется запись, которую дольше
всех не использовали.


## Программа
Создайте в папке задачи программу `cache.py` (имя может быть другим - см. README курса).

**Запуск:** `python cache.py КАТАЛОГ [--size N] [--delay СЕК]` (параметры - в любом порядке).
- `КАТАЛОГ` - файл «внешнего источника» в UTF-8, по строке `артикул; товар` (см. пример).
- `--size N` - лимит быстрых записей, целое число больше 0; по умолчанию 1 000.
- `--delay СЕК` - сколько секунд «думает» источник при каждом обращении к каталогу, число ≥ 0
  (можно дробное, например `0.2`); по умолчанию 0.

**Команды** читаются из стандартного ввода, по одной в строке.
Команды пишутся строчными буквами; артикул - всё после команды, без пробелов по краям
(внутри артикула пробелы и любые символы допустимы, кроме `;` в `put`).

| Команда | Ответ |
|---|---|
| `get артикул` | `артикул: "товар"` (из кэша и из источника - одинаково) или `артикул: [товар не найден]` |
| `put артикул; товар` | `артикул: сохранено` - записать или обновить товар прямо в кэше, без источника |
| `del артикул` | `артикул: удалено`; если артикула в кэше нет - строка `артикул: …` с любым текстом (это не ошибка) |
| `list` | `Список (3 из 1 000): K3, K1, K2` - артикулы от самого свежего к самому давнему; второе число - лимит кэша; пустой - `Список (0 из 1 000): пусто` |

Неверная команда (неизвестная, пустой артикул, `put` без значения) - строка `ОШИБКА: <описание>`,
программа продолжает работу. Числа от 1000 печатаются с пробелом между разрядами: `12 345`.


## Договорённости
- Найденный товар сохраняется в кэш, ненайденный - нет (каждый такой запрос снова идёт в источник).
- `get` и `put` делают запись самой свежей; при переполнении вытесняется самая давняя (LRU).
- `put` существующего артикула обновляет товар без дубликата, запись становится самой свежей.
- Артикулы, похожие друг на друга (`ab` и `ba`, `SKU-12` и `SKU-21`), - разные артикулы.
- 100 000 запросов при лимите 100 обрабатываются за секунды.

## Пример
Каталог `catalog.txt`:
```
SKU-1001; Смартфон X-Pro, 128 ГБ, чёрный
SKU-2045; Наушники беспроводные SoundMax
SKU-3300; Чехол для смартфона силиконовый
```
Команды (`python cache.py catalog.txt < commands.txt`):
```
get SKU-1001
get SKU-2045
get SKU-1001
get SKU-3300
get SKU-9999
get SKU-2045
```
Вывод:
```
SKU-1001: "Смартфон X-Pro, 128 ГБ, чёрный"
SKU-2045: "Наушники беспроводные SoundMax"
SKU-1001: "Смартфон X-Pro, 128 ГБ, чёрный"
SKU-3300: "Чехол для смартфона силиконовый"
SKU-9999: [товар не найден]
SKU-2045: "Наушники беспроводные SoundMax"
```

Тот же каталог с лимитом 2 (`python cache.py catalog.txt --size 2 < commands.txt`):
```
get SKU-1001
get SKU-2045
get SKU-1001
get SKU-3300
list
put SKU-2045; Наушники SoundMax Pro
del SKU-3300
list
```
Вывод (`SKU-3300` вытесняет давно не использованный `SKU-2045`, а `put` - `SKU-1001`):
```
SKU-1001: "Смартфон X-Pro, 128 ГБ, чёрный"
SKU-2045: "Наушники беспроводные SoundMax"
SKU-1001: "Смартфон X-Pro, 128 ГБ, чёрный"
SKU-3300: "Чехол для смартфона силиконовый"
Список (2 из 2): SKU-3300, SKU-1001
SKU-2045: сохранено
SKU-3300: удалено
Список (1 из 2): SKU-2045
```

## Git-сценарий (параллельные эксперименты)
Всё делается в общем репозитории курса, в ваших ветках и тегах: вместо `<логин>` - ваш логин в edu.susu.
Ваша «главная» ветка - `<логин>/main`; если её ещё нет, создайте от `main`: `git switch -c <логин>/main main`.
Ветки и теги отправляйте в репозиторий: `git push origin <ветка> <тег>…`. Не удаляйте ветки, которые нужны для проверки.

1. Создайте ветку разработки: `git switch -c <логин>/develop main`.
2. От неё - две ветки экспериментов: `<логин>/experiment/chaining` (хэш-таблица с цепочками) и
   `<логин>/experiment/open-addressing` (открытая адресация). В каждой реализуйте свою стратегию
   и закоммитьте.
3. Замерьте скорость обеих на 10, 1000 и 100 000 записей (например, временем работы программы на
   большом каталоге) и запишите результаты и вывод в `tasks/t02_cache/EXPERIMENT.md`.
4. Лучшую ветку слейте в `<логин>/develop`. На вторую поставьте тег `<логин>-t02-rejected`
   (`git tag <логин>-t02-rejected <логин>/experiment/…`) - так её коммиты сохранятся - и удалите
   ветку: `git branch -D …`, а если она уже отправлена - `git push origin --delete …`.
5. Закоммитьте `EXPERIMENT.md` в `<логин>/develop`, отправьте ветки и тег.

Что проверяется: есть `<логин>/develop`; осталась ровно одна ветка эксперимента, и она влита в
develop; отклонённая сохранена тегом `<логин>-t02-rejected` и в develop не попала; оба эксперимента
начаты от develop; в develop есть `EXPERIMENT.md` с замерами обеих стратегий (числами) и выводом.
